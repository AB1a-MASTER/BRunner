PURPOSE

This file is the concise starting point for the next development session. Read
`README.md` and then `docs/BRUNNER_MASTER_ROADMAP.md`. The README owns the
product boundary; the roadmap owns milestone order and current priority. This
handoff records the immediate working state and must not become a second
roadmap.

CURRENT PRODUCT BOUNDARY

- BRunner currently targets Chrome or a compatible Chromium browser plus a
  local Windows companion application.
- The extension owns workflow authoring/execution, tabs/pages, browser actions,
  the mapper engine, and post-action checks.
- The companion owns local workflow persistence, approved-folder operations,
  process status, and explicitly requested visible operating-system assistance.
- The product assumes one cooperating local user and one selected browser
  profile at a time.
- Cross-platform desktop support, remote/multi-user service, headless/cloud
  operation, and unattended deployment are not current scope.

TRUST AND DATA BOUNDARY

- The project does not currently guarantee credential protection, sensitive-data
  handling, complete redaction, secret-safe logs, or privacy-safe saved maps.
- Existing masking is defensive behavior, not a supported security promise.
- Use synthetic, disposable data for all development and acceptance. Do not use
  real passwords, tokens, payment data, private messages, or confidential files.
- The companion target is a cooperative one-profile host lock using a stable,
  non-secret per-profile instance ID. There is no pairing key or authentication
  claim. Transitional key-based source remains to be replaced.
- Do not describe the current pairing flow as a security boundary.

CURRENT PRIORITY

Mapper engine and reliability closure is the active milestone.

Focus on:

1. workflow/page-scoped component identity;
2. deterministic primary-first resolution;
3. strict uniqueness and ambiguity refusal;
4. stable reconciliation under verified page drift;
5. node-neutral structured resolution outcomes that later finalized nodes can
   route without guessing;
6. static-map reliability alongside bounded dynamic content;
7. verified open Shadow DOM and extension-accessible frame behavior within
   supported fixtures;
8. concurrent-safe, revisioned mapper persistence with bounded large-page and
   quota behavior;
9. deterministic tests and focused live extension acceptance using synthetic
   repository fixtures.

The existing Mapper Inspector is an engineering diagnostic surface for this
work. Do not spend the current milestone polishing it into a final saved-map
product. A polished saved-map viewer, its final review workflows, responsive UI,
and visual design are deferred to V2.

NODE CATALOG RULE

`workflow_nodes_implementation_blueprint.md` is the sole finalized node catalog.
Earlier catalogs and the currently registered nodes describe provisional
development behavior only.

Do not add, rename, consolidate, redesign, or remove provisional nodes before the
node milestone. Mapper-unblocking correctness fixes are the only exception.
During the node milestone, follow the blueprint definition of done and track
upgrade, rewrite/change, add, and removal status. Current actions are reference
code, not a compatibility contract.

Do not implement graph branching, loops, joins, or error paths in the linear
executor. They require graph traversal, explicit ports, validation, limits, and
cancellation semantics.

active mapper milestone:

  per-run variables;
- Graph Studio, graph persistence, legacy adapters, and mapper schema-v3
  `success`/`unresolved` traversal;
- current provisional browser, element, wait, data, file, clipboard, download,
  screenshot, and host-backed actions;
- Windows companion source for workflow storage, approved folders, diagnostics,
  transitional pairing/connection plumbing, and visible fallback foundations;
- mapper core/coordinator/store, component identities, reconciliation,
  diagnostics, fixtures, and the engineering Inspector.

This list records existing source, not final product acceptance. Do not infer
that the mapper, viewer, node catalog, security posture, or release is complete.
